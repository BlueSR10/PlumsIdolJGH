# 맵 디자인 가이드 (초보자용)

> 맵 디자이너용. Unity를 처음 써도 따라 할 수 있게 적었다. 값은 아직 직접 플레이 테스트를 거치지 않은 임시 값이라 바뀔 수 있다.

## 0. 시작 전에

1. Git에서 최신으로 pull 한다. Unity 버전은 **6000.3.20f1**이다.
2. Unity로 프로젝트를 연다. 위쪽 메뉴 바(File, Edit, Assets, GameObject, Component …)에 **Plum** 메뉴가 보이면 준비 완료다. 안 보이면 Unity 창을 한 번 클릭하거나 Ctrl+R(Refresh)을 누른다.

### 내가 만지는 것 / 만지지 않는 것

| 만져도 되는 것 | 만지면 안 되는 것 |
|---|---|
| 내 `Assets/Prefabs/Maps/Map_내이름.prefab` | `Assets/Prefabs/StageRig.prefab` |
| 내 `Assets/Scenes/Stage_내이름.unity` | `Assets/Prefabs/Palette/`의 원본 조각 |
| 내 `Assets/Prefabs/Gimmicks/내이름/` (프리팹 변형, 내가 만든 기믹) | `Assets/Scripts/Runner/`, `Assets/Scripts/Editor/`, `ProjectSettings/` |
| 내 `Assets/Scripts/Gimmicks/내이름/` (새 동작이 필요할 때만, 9장) | 다른 사람의 `Gimmicks/` 폴더 |
| | 다른 사람의 `Map_*`, `Stage_*` |

원본을 고쳐야 할 것 같으면 직접 고치지 말고 프로그래머에게 말한다.

## 1. 새 스테이지 만들기

1. 메뉴 **Plum > New Stage**를 연다.
2. 이름을 입력하고 **만들기**를 누른다. 영문/숫자로 쓰고 공백은 쓰지 않는다. 예: `Forest1`
3. 아래가 자동으로 만들어진다.
   - 씬 `Assets/Scenes/Stage_Forest1.unity`
   - 맵 프리팹 `Assets/Prefabs/Maps/Map_Forest1.prefab` (바닥 170 + Goal이 들어 있음)
   - 이동 스냅 0.5 켜짐

## 2. 맵 편집 화면 열기

1. Hierarchy(왼쪽 목록)에서 `StageRig` > `Stage` > `Map_Forest1`을 찾는다.
2. `Map_Forest1`을 **더블클릭**한다. 화면이 Prefab 모드로 바뀌고 맵 조각만 보인다. 여기서 작업한다.
3. 작업이 끝나면 Hierarchy 위쪽의 **← 화살표**로 나온다. 바뀐 내용은 저장해야 한다 (Ctrl+S, 또는 Prefab 모드 위쪽의 **Auto Save** 체크).

## 3. 조각 배치하기

`Assets/Prefabs/Palette/`에서 조각을 **Hierarchy의 `Map_Forest1` 위로 끌어다 놓는다.** 그러면 `Map_Forest1`의 자식으로 들어가고 바닥에 맞는 기본 높이로 생긴다. Scene 화면에 바로 끌어다 놓으면 높이가 어긋나거나 `Map_Forest1` 밖에 생길 수 있다.

놓은 뒤 Inspector의 **Position Y**가 아래 표와 같은지 확인한다 (표에 없는 값이면 고친다).

| 조각 | Position Y |
|---|---|
| Spike, Block(바닥) | -0.86 |
| Bar, Block(매달기) | -0.26 |
| 소형화 통로용 Block (Scale Y 0.5) | -0.46 |
| Gate | 2.19 |
| Item_* | -0.61 |
| Goal | 1.39 |
| Ground | -1.61 |

| 조각 | 뜻 | 크기 조절 |
|---|---|---|
| Ground | 바닥. 길이 20 | 이어 붙인다 (x 간격 20) |
| Spike | 가시. 닿으면 사망. **점프해서 넘는다** | Scale X = 폭, Scale Y는 0.5 유지 |
| Bar | 공중에 뜬 막대. 닿으면 사망. **슬라이드로 밑을 지나간다** | Scale X = 폭 |
| Gate | 위아래로 움직이는 벽. 내려와 있을 때 닿으면 사망. **타이밍을 보고 감속해서 통과**. 파괴할 수 없다 | Inspector의 Period(주기), Phase(시작 타이밍) |
| Block | **파괴 불가 장애물.** 닿으면 사망. 거대화 중에도 못 부순다. 크기와 배치는 Spike, Bar와 같게 쓴다(스프라이트만 다를 예정) | Scale X = 폭 |
| Item_Giant | **거대화 아이템.** 5초 동안 커진다. 커진 동안 Spike, Bar에 닿으면 부수고 지나간다 (Block, Gate는 못 부숨) | 위치만 옮긴다 |
| Item_Small | **소형화 아이템.** 5초 동안 작아진다. 슬라이드보다 낮은 틈(높이 0.4 이하)을 지나갈 수 있다 | 위치만 옮긴다 |
| Item_Boost | **가속 아이템.** 2초 동안 속도가 +4 빨라진다. 넓은 가시를 넘거나, 반대로 너무 빨라서 죽는 구간에 쓴다 | 위치만 옮긴다 |
| Bird | **날아오는 장애물(새).** 크기 약 0.7×0.35(아트 캔버스는 64×32). 플레이어가 가까워지면(거리 10 이하) 왼쪽으로 날아온다. 닿으면 사망. **높이는 놓은 위치 그대로**라서 Y -0.86이면 점프로, -0.26이면 슬라이드로 피한다. 높이 두면 비행 중에만 마주친다. 거대화로 부술 수 있다. 선택하면 Scene 화면에 날아갈 경로(노란 선)가 보인다 | 위치만 옮긴다. Inspector의 Fly Speed(날아오는 속도), Trigger Distance(날기 시작하는 거리) |
| Goal | 닿으면 클리어. 스테이지 끝에 **하나만** | 위치만 옮긴다 |

Spike, Bar, Bird는 파괴 가능이고 Block, Gate는 파괴 불가다. 아이템 지속 시간과 수치는 임시 값이다.

### 단계별 아트 조각 (1~3단계)

팔레트에 단계별 조각이 있다. 이름이 `S1_`(집 밖), `S2_`(집 안 주방), `S3_`(오븐)로 시작한다. 바닥은 단계에 맞는 `S?_Ground`를 쓴다.

| 종류 | 조각 | Position Y | 크기 조절 |
|---|---|---|---|
| 바닥 | S1_Ground, S2_Ground, S3_Ground | -1.61 | 길이 20, 이어 붙인다 |
| 낮은 장애물 (점프) | S1_Thorn, S2_Crystal, S3_Fire | 프리팹 기본값 그대로 | **Width** (그림 한 장 폭의 배수) |
| 키 큰 장애물 (파괴 불가) | S1_Vine, S2_Flask, S3_FireLong | 프리팹 기본값 그대로 | 위치만 |
| 매달린 장애물 (슬라이드) | S1_Bud, S2_Knife, S2_Ladle, S2_Spatula, S3_Fork | 프리팹 기본값 그대로 | 위치만 |
| 발판 (올라서는 곳, 아래에서는 통과) | S1_Platform, S2_Shelf, S3_Platform | 0.2 (윗면이 바닥에서 1.56 높이). 높이는 바꿔도 된다 | **Width** |

- 이 조각들은 **Scale을 바꾸지 않는다.** 폭은 Inspector의 **Art Piece > Width**에서 바꾼다 (Repeat Width가 켜진 조각만).
- Y는 놓을 때 정해진 높이로 생긴다. 건드리지 않는다. 충돌 크기는 임시라서 실제로 죽는 위치가 이상하면 알려 준다.
- 단계 순서(집 밖 → 집 → 오븐)에 맞춰 한 스테이지에는 한 단계 조각만 쓴다. 배경도 같은 단계로 고른다 (집 안 = BG_Kitchen, 오븐 = BG_Oven).

### 퍼즐 설계 팁

이 게임은 **시행착오로 푸는 퍼즐**이다. 어떤 속도로 갈지, 아이템을 먹을지 말지, 비행을 언제 쓸지에 따라 클리어 여부가 갈리게 만든다.
- 아이템은 **안 먹고 지나갈 길**도 있게 두면 선택이 된다. 먹어야만 깰 수 있는 곳도, 먹으면 오히려 못 깨는 곳(거대화하면 Gate 앞에서 사망, 가속하면 짧은 구간에서 사망)도 만들 수 있다.
- 아이템은 죽으면 다시 나타난다. 먹은 아이템 효과도 재시작하면 사라진다.
- 소형화 전용 통로는 위에 Block을 매달아 만든다. 바닥에서 Block 아래까지의 틈을 **0.4**로 하면 일반 슬라이드(0.45)는 못 지나가고 소형화만 지나간다. 예시는 `Map_Gimmicks`를 연다.

### 위치 옮기기
- Scene 화면에서 조각을 클릭하고 **빨간 X 화살표**를 좌우로 끌면 0.5씩 움직인다. **Y(초록 화살표)는 건드리지 않는다.** 위 표의 높이가 바닥에 맞는 값이다.
- 정확한 값은 오른쪽 Inspector의 **Transform > Position X**에 숫자를 직접 입력한다.
- 폭 바꾸기는 Inspector의 **Scale X**에 입력한다 (가시 폭 5 = Scale X 5).

### 좌표 감각
- 1유닛은 캐릭터 한 칸 정도(64px)다. 화면은 가로 10, 세로 약 5.6유닛이다.
- 플레이어 시작 위치는 **x = -2**다. 맵은 오른쪽(+x) 방향으로 만든다.
- 감속 없이 달릴 때 대략 이 위치에서 그 순간이 온다.

| 시작 후 | 맵 x 위치 | 그때의 속도 |
|---|---|---|
| 10초 | 약 43 | 5 |
| 20초 | 약 98 | 6 |
| 30초 | 약 163 | 7 |

## 4. 속도 설정

루트 `Map_Forest1`을 선택하고 Inspector의 **Stage Settings**에서 조정한다.

| 항목 | 기본값 | 뜻 |
|---|---|---|
| Start Speed | 4 | 시작 속도 |
| Acceleration | 0.1 | 초당 빨라지는 정도 |
| Chaser Speed | 4.5 | 쫓아오는 쿠키 속도 (일정) |
| Chaser Start Gap | 8 | 시작할 때 쿠키와의 거리 |

- **배경 선택**: 같은 Inspector의 **배경 선택** 팝업에서 산, 사막, 묘지, 눈, 주방(BG_Kitchen), 오븐(BG_Oven) 중에서 고른다. 선택한 배경은 Play할 때 나타난다 (Prefab 모드에서는 보이지 않는다). "(없음)"을 고르면 배경이 없다.
- **다음 스테이지**: 같은 Inspector의 **스테이지 전환 > 다음 스테이지**에서 클리어 후 이어질 스테이지를 고른다. 클리어하면 화면이 어두워졌다가 다음 스테이지로 넘어간다. "(없음)"이면 같은 스테이지를 다시 시작한다. 목록에 없는 씬은 프로그래머에게 등록을 부탁한다.
- Inspector 아래쪽 **맵 검증**에 Goal 유무, 시작 바닥, 예상 시간(목표 30초)이 나온다. 빨간 오류는 반드시 고친다.
- 쿠키 속도가 내 속도보다 느리면 감속하지 않는 한 안 잡힌다. 그래서 속도를 너무 낮게 시작하면 쿠키가 따라잡는다. 감속하면서 플레이해 보며 맞춘다.

### 가시 폭과 필요한 속도 (참고)
점프 거리는 속도에 비례한다. 가시 높이는 0.5다.

| 가시 폭 | 필요한 최소 속도 | 방법 |
|---|---|---|
| 2.5 | 약 5.2 | 1단 점프 |
| 5 | 약 4.3 | 2단 점프 |
| 7 | 약 5.9 | 2단 점프 (이보다 넓으면 못 넘는다) |

## 5. 테스트하기

1. Prefab 모드에서 나와 저장한 뒤 **Play(▶)**를 누른다.
2. 조작: 점프 `Space`/`↑`/`W` (공중에서 한 번 더 누르면 2단 점프), 슬라이드 `S`/`↓`, 감속 `Left Shift`, 비행 `E`(스테이지당 1회, 5초).
3. 죽으면 약 1초 뒤 처음부터 다시 시작한다. 체크포인트는 없다.
4. Scene 화면에는 **초록 선**(플레이어 시작 위치)과 **회색 박스**(첫 화면 범위)가 보인다.

## 6. 주의점 (꼭 읽기)

1. **Play 중에 바꾼 값은 Play를 끄면 사라진다.** 값을 조정하고 싶으면 Play를 끈 뒤에 바꾼다.
2. **Inspector에서 Overrides > Apply All을 누르지 않는다.** 팔레트 조각의 Scale이나 위치를 바꾼 뒤 Apply를 누르면 원본 팔레트가 바뀌어 모든 사람의 맵이 망가진다. Scale을 바꾸기만 하고 그대로 둔다.
3. **팔레트 폴더의 조각을 더블클릭해서 열지 않는다.** 원본이다.
4. **`StageRig`를 수정하지 않는다.** 위치를 옮기거나 지우면 게임이 안 돌아간다. 내 일은 `Map_내이름` 안에서 끝난다.
5. **바닥이 끊기면 구멍이다.** 플레이어가 6유닛 이상 떨어지면 사망한다. 구멍을 일부러 만들 때는 점프로 넘을 수 있는 폭인지 확인한다. 시작 위치(x=-2)에는 반드시 바닥이 있어야 한다.
6. **Goal은 하나만, 맨 끝에.** Goal 뒤에도 바닥이 **15유닛 이상** 있어야 한다 (다음 스테이지로 넘어가는 동안 계속 달린다). Goal이 없으면 클리어가 안 된다.
7. **시작 직후는 비워 둔다.** 처음 10유닛 정도는 장애물을 두지 않는다. 플레이어가 상황을 파악할 시간이 필요하다.
8. **깰 수 없는 배치를 만들지 않는다.** 가시 폭이 너무 넓거나, 가시와 막대가 붙어서 점프와 슬라이드를 동시에 해야 하면 못 깬다. 만든 뒤 반드시 내가 직접 클리어해 본다.
9. **스테이지 길이는 감속 없이 30초 정도**를 목표로 한다. 맵 검증의 예상 시간을 본다.
10. **Z 값은 0으로 둔다.** 조각이 안 보이거나 충돌이 안 되는 원인이 된다.
11. **빈 곳에 조각을 놓지 않는다.** `Map_내이름`의 자식이 아니면 맵이 스크롤될 때 같이 움직이지 않고 제자리에 있다. Hierarchy에서 들여쓰기를 확인한다.
12. Undo는 **Ctrl+Z**다. 실수하면 바로 되돌린다.

## 7. 저장하고 올리기 (Git)

- 올릴 파일은 **내 것만**이다. `.meta` 파일도 같이 올린다 (없으면 연결이 끊어진다).
  - `Assets/Scenes/Stage_이름.unity`, `.meta`
  - `Assets/Prefabs/Maps/Map_이름.prefab`, `.meta`
- 작업 전에 항상 pull, 큰 변경 전에는 commit 한다.
- 다른 사람의 맵 파일이 충돌로 보이면 건드리지 말고 프로그래머에게 알린다.

## 8. 문제가 생기면

| 증상 | 확인 |
|---|---|
| Plum 메뉴가 없다 | Unity 창 클릭 또는 Ctrl+R. 안 되면 Console의 빨간 에러를 프로그래머에게 보여 준다 |
| Play 했는데 캐릭터가 바로 떨어진다 | 시작 위치(x=-2) 바닥, 맵 검증 오류 확인 |
| 조각이 화면에서 안 보인다 | Z=0인지, `Map_내이름` 자식인지 확인 |
| Gate가 안 움직인다 | Play 중인지 확인 (Prefab 모드에서는 움직이지 않는다) |
| 클리어가 안 된다 | Goal이 하나 있는지, 맵 검증 확인 |
| 값을 바꿨는데 반영이 안 된다 | Play를 끄고 바꿨는지, 저장했는지 확인 |

앞으로 트램펄린, 부서지는 발판 같은 새 기믹이 생기면 팔레트에 조각이 추가된다.

## 9. 기믹을 바꾸거나 새로 만들 때 (꼭 읽기)

준비된 팀원 폴더: `Assets/Scripts/Gimmicks/`와 `Assets/Prefabs/Gimmicks/` 아래의 **상연, 은호, 강현** (빈 폴더는 `.gitkeep`으로 유지한다. 파일을 넣으면 지워도 된다).

팔레트 조각에 없는 모습이나 동작이 필요할 때는 **아래 세 단계 중 가장 위에 있는 방법**을 쓴다. 위 단계로 되면 아래 단계로 내려가지 않는다.

| 상황 | 방법 | 저장되는 곳 |
|---|---|---|
| 한 군데에서만 값이 다르다 | **맵 안의 조각(인스턴스)을 직접 수정**한다. Inspector에서 Width, Period, Fly Speed 같은 값을 바꾼다 | 내 `Map_내이름` 프리팹 |
| 같은 조정을 **두세 번** 쓰게 됐다 | **Prefab Variant**로 만든다. 팔레트 조각을 우클릭 > Create > Prefab Variant | `Assets/Prefabs/Gimmicks/내이름/` |
| **새 동작**이 필요하다 (지금 있는 값으로는 안 된다) | **스크립트를 작성**하고 프리팹으로 묶는다 | 스크립트 `Assets/Scripts/Gimmicks/내이름/`, 프리팹 `Assets/Prefabs/Gimmicks/내이름/` |

### 지켜야 할 것

1. **Apply 금지.** 인스턴스나 변형에서 Overrides > **Apply All**을 누르지 않는다. 팔레트 원본이 바뀌어 모두의 맵이 망가진다. 변형은 새 파일로 만들기만 한다.
2. **같은 조정을 세 번째 쓰게 되면 변형으로 바꾼다.** 인스턴스 수정이 맵 여기저기 흩어지면 나중에 찾기 어렵고 값을 한 번에 못 바꾼다. 변형 이름은 `내이름_설명`으로 짓는다 (예: `kim_FastBird`).
3. **자기 폴더에만 쓴다.** `Assets/Scripts/Runner/`, 팔레트 원본, `StageRig`는 프로그래머만 수정한다. 다른 사람의 `Gimmicks/` 폴더도 건드리지 않는다.
4. **컴파일 오류가 있는 스크립트는 커밋하지 않는다.** 오류가 하나라도 있으면 pull한 사람 모두의 Unity가 Safe Mode로 열린다. 커밋하기 전에 Console에 빨간 오류가 없고 Play가 되는지 확인한다.
5. **클래스 이름은 겹치지 않게 짓는다.** 다른 사람의 스크립트와 이름이 같으면 컴파일 오류가 난다. 각자 정한 영문 접두사를 이름 앞에 붙인다 (접두사가 `Kh`라면 `KhSwingBlade`).
6. **`.meta` 파일도 같이 커밋한다.** 스크립트, 프리팹, 폴더 모두 해당된다. 없으면 연결이 끊어진다.
7. **원본 구성을 믿지 않는다.** 프로그래머가 팔레트 원본에 값을 추가하는 것은 변형에 영향이 없다. 삭제하거나 이름을 바꾸면 변형이 깨질 수 있으니 그럴 때는 미리 알린다.
8. **Play 중에 바꾼 값은 Play를 끄면 사라진다.** 값을 정할 때는 Play를 끄고 바꾸고 저장한다.
9. **직접 깨 본다.** 만든 구간은 반드시 자기가 클리어해 본다 (6장 8번과 같다).

### 새 동작 스크립트를 쓸 때 (코드를 쓰는 사람용)

- **죽는 판정은 `Hazard` 컴포넌트를 같이 붙인다.** 직접 `RunManager.Instance.Die()`를 부르지 않는다. 그래야 거대화로 부수는 규칙(Destructible)이 똑같이 적용된다. 충돌 상자는 Trigger로 둔다.
- **재시작하면 처음 상태로 돌아가야 한다.** 상태가 있는 기믹은 `StageReset.Requested`를 구독해서 위치와 값을 되돌린다. `Awake`에서 구독하고 `OnDestroy`에서 해제한다.
- **사망/클리어 중에는 움직이지 않는다.** `RunManager.Instance.Current == RunManager.State.Running`일 때만 갱신한다.
- **시간 기준 동작은 `RunManager.Instance.StageTime`을 쓴다.** 그러면 시도마다 같은 타이밍이 된다 (Gate가 그렇게 한다).
- **플레이어와의 거리 기준 동작**은 `FindFirstObjectByType<PlayerController>()`의 위치를 쓴다.
- **참고용 예시:** `Assets/Scripts/Runner/FlyingHazard.cs`(거리 기준으로 움직이는 장애물, 재시작 복귀 포함)와 `MovingHazard.cs`(시간 기준 왕복). 둘 다 짧으니 먼저 읽고 따라 한다.
- **여러 맵에서 쓸 만하면** 프로그래머에게 팔레트로 올려 달라고 요청한다. 그전까지는 자기 폴더에 둔다.
- 공용 부모 클래스(재시작 처리를 대신해 주는 틀)는 **아직 없다.** 필요하면 프로그래머에게 말한다.

### 막혔을 때

원본을 고쳐야 할 것 같거나, 아래 중 하나에 해당하면 혼자 해결하지 말고 프로그래머에게 말한다.
- `Runner/` 스크립트를 수정해야 하는 경우
- 팔레트 원본에 값이나 기능이 더 필요한 경우
- 컴파일 오류의 원인을 모르겠는 경우
