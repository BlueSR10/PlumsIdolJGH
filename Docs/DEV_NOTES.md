## M6.1 구현

- 공중 장애물 `FlyingHazard`(팔레트 `Bird`, `Hazard`와 함께 쓰고 destructible, 충돌 0.7×0.35, 아트 캔버스 64×32 — 그림이 들어오면 Visual 자식의 스프라이트만 교체): 플레이어와의 가로 거리가 `triggerDistance`(기본 10) 이하가 되면 스테이지에 대해 `flySpeed`(기본 3)로 왼쪽으로 날아온다. 거리 기준이라 속도 조절에 따라 도착 시점이 달라진다. 높이는 놓은 위치 그대로(Bar와 같은 -0.26이면 슬라이드, -0.86이면 점프, 높이 두면 비행 중에만 마주침). 재시작하면 처음 자리로 복귀. 테스트 씬 `Stage_Test_Bird`. 움직임 변형(위아래 흔들림, 방향 전환 등)은 안 했다.
- 스테이지 전환(GDD 8.4): 맵 루트 `StageSettings`의 "다음 스테이지" 팝업(Build Settings 씬 목록)으로 정한다. 비우면 클리어 후 같은 스테이지 반복(기존 동작). 클리어 → 0.6초 후 화면이 0.9초 동안 어두워지고(마녀 스프라이트만 정렬 순서를 올려 어둠 위에 남김, `ScreenFade`) 0.6초 유지 → 씬 로드 → 어두운 채로 멈추지 않고 이어 달리며 밝아진다(새 스테이지는 자기 시작 속도로 출발, 시작 부분은 비워 둬야 안전). 클리어해도 멈추지 않고 계속 달린 채 어두워진다(다음 스테이지가 없으면 멈추고 반복). 전환 중 HUD는 숨긴다(`RunManager.HideHud`). 수치는 `RunManager` Inspector.
- 다음 스테이지 지정 예: `Map_Art_1` → `Stage_Art_2` → `Stage_Art_3`. 그 밖의 맵은 지정하지 않았다. 씬 로드는 Build Settings에 있어야 하므로 `Stage_Gimmicks`와 `Stage_Test_*`를 등록해 두었다. 새 스테이지를 이어 붙일 때는 그 씬도 Build Settings에 넣는다.

## 아트 연결

- 마녀: `Player` 프리팹의 `Visual`에 Animator(`Assets/Animation/마녀/Witch.controller`), `PlayerAnimator`가 상태별로 Play(Run/Sit(착지)/Slide/Jump/DJump/Broom/Brake(감속 키를 누르는 동안, `SpeedController.Braking`)/Dead(사망·포획, 우선순위 최상)). 컨트롤러에는 전환이 없어 아티스트 파일은 수정하지 않았다. 달리기 속도는 스크롤 속도에 비례. 슬라이드 자세는 애니메이션이 그리므로 스프라이트를 눌러 늘리지 않고, 거대화·소형화 배율만 스프라이트에 적용한다.

## 이펙트 (`PlayerEffects`, `Assets/Prefabs/Effects/`)

- `Player` 프리팹 아래 `FX_Dust`(슬라이드 먼지), `FX_Spark`(브레이크 불꽃, 지상일 때만), `FX_Hit`(피격), `FX_Debris`(장애물 파괴 파편), `FX_DoubleJump`(2단 점프 순간 발밑에서 도는 흰 입자, 수치는 `PlayerEffects`의 Swirl 항목) 파티클을 두고 `PlayerEffects`가 위치·속도·양만 정해 Emit한다. 모양(크기·수명·색·중력)은 FX_* 프리팹에서 조정. 지금은 그림 없이 네모 점이고, 아티스트 스프라이트가 오면 FX 프리팹의 Renderer 머티리얼/Texture Sheet Animation에 연결한다.
- 마녀가 화면 고정이고 바닥이 스크롤되므로 월드 공간 파티클에 스크롤 속도만큼 왼쪽 속도를 더한다.
- 피격: `RunManager.Died` 이벤트 → 파티클 + 흰색 번쩍임(`Plum/SpriteFlash` 셰이더, `Witch_Flash` 머티리얼) + 가로 카메라 흔들림 + 0.07초 정지. 파괴 파편은 `Hazard.Broken` 이벤트. 수치는 `PlayerEffects` Inspector. 소리도 같은 이벤트에 붙이면 된다.
- 키 입력은 자동화로 안 들어가서 슬라이드 먼지 외에는 코드 경로로 직접 확인했다 (브레이크 입력 조건은 슬라이드와 같은 방식). **브레이크 불꽃과 전체 느낌은 직접 플레이로 확인이 필요하다.**

## 기술 규약

- Full HD(1920×1080), URP 2D, Pixel Perfect Camera
- 스프라이트: 캔버스 64×64, PPU 64, Filter Point, Compression None
- 기준 해상도: 640×360 (3배, 캐릭터가 화면 높이의 1/5.6). 카메라 y=0.703125 (바닥을 화면 하단에 맞춤)
- 월드 구조: 플레이어는 화면 고정, `Stage`(kinematic)가 왼쪽으로 스크롤
- 입력: `RunnerInput`에서 코드로 정의 — 점프 Space/↑/W, 슬라이드 S/↓, 감속 LeftShift, 마녀 능력(비행) E
- `Assets/Placeholders/`: 임시 사각형 스프라이트. 실제 아트 연결 후 삭제

## 임시 값 (기획 확정 시 삭제)

- 속도 조절: 기준 속도가 계속 증가(4 + 0.1/s²) + 감속 키, 키를 떼면 기준 속도로 복귀
- 점프: 1단 높이 1.8, 2단 1.6(기존 1.2에서 상향), 중력 배율 2 (1단 체공 0.86초). 슬라이드 시 충돌 높이 50%
- 공중에서는 속도를 현재 값으로 유지하고 마녀 비행 중(`PlayerController.Flying`)에만 조절
- 마녀 비행(`WitchFlight`): 5초, 상하 이동 4.5/s, 시작 높이 +3까지, 스테이지당 1회(재시작 시 복구). 비행 중에도 장애물에 닿으면 사망. 종료 후 착지 전까지 공중 점프 없음
- 가시(높이 0.5) 위 체공: 1단 0.73초, 2단 최대 약 1.43초(2단 1.2 기준, 1.6으로 올리면 약 0.1초 늘어남). 폭 w를 넘는 최소 속도 ≈ (w + 0.5) ÷ (체공 − 0.15)
  - 1단만: w=2.5에 5.2, 2단 사용(1.2 기준): w=5에 4.3, w=7에 5.9. 기존 맵의 넓은 가시는 2단이 높아져 더 쉬워졌으니 플레이하며 확인
- 변신 아이템(`PlayerForm`): 거대화 ×2, 소형화 ×0.4(슬라이드 높이보다 낮아야 소형화 전용 통로가 가능), 둘 다 5초. 발 위치는 고정하고 위로 늘고 줄며, 새 변신을 먹으면 교체된다. 사망·재시작 시 해제
- 가속 아이템(`SpeedController.Boost`): 스크롤 속도 +4를 2초. 감속 키는 기본 속도에만 적용되고 가속 보너스는 그대로 더해진다
- Gate(움직이는 장애물): 주기 3초, 닫힘 약 43%. 감속으로 도착 타이밍을 늦춰 통과
- 추격자: 속도 4.5, 시작 거리 8, 잡히는 거리 0.6 (쿠키 그림 앞끝 0.375 + 마녀 충돌 반폭 0.25. 임시 사각형 때의 1.25는 그림이 작아지며 닿기 전에 죽는 원인이었음. 스테이지별 조정 예정). 사망 후 0.8초 뒤, 클리어 2.5초 뒤 스테이지 처음부터 재시작
- 재시작 시 속도·기준 속도·스테이지 시간(Gate 타이밍)을 시작 값으로 복원
- 진행 막대바와 속도 표시는 임시 IMGUI
